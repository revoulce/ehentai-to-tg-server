# Анализ источника: настройка и границы 0.2

## Установка

Настройте `.env` по примеру в корне сервера. Дополнительная зависимость источника
не требуется для запуска одного HTTP API.

```sh
uv sync --locked --extra source
uv run --locked --extra source ehtg source probe
```

`probe` не делает сетевых запросов. Он проверяет установленную версию gallery-dl
**1.32.17**, SHA-256 E-Hentai extractor и распознавание допустимого gallery URL.
Исходник — архив Codeberg по полному commit SHA; хеш закреплён в pyproject/uv.lock,
а прямой URL с хешем присутствует и в metadata собранного wheel.
Произвольная текущая поставка из PyPI не заменяет эту зависимость.

## Авторизованная сессия

Следующие команды предназначены для сервера с фактическим доступом к источнику.
Передайте cookie jar на сервер защищённо, затем выполните локальную команду:

```sh
uv run --locked --extra source ehtg source import-cookies /secure/path/e-hentai-cookies.txt
uv run --locked --extra source ehtg source status
```

Принимается Mozilla/Netscape cookie jar размером до 64 KiB. Отбираются только
`ipb_member_id` и `ipb_pass_hash` домена `e-hentai.org`/`.e-hentai.org`, с путём `/`.
Остальные домены и cookies не сохраняются. Нулевой срок в Netscape означает
session cookie; известный истёкший срок отклоняется.

Содержимое передаётся дочернему процессу по stdin, не через аргументы, HTTP API
или Telegram. Кандидат проверяется по авторизованной странице `home.php`:
неизвестная разметка не выдаётся за успешный вход. Конкретную разметку и сессию
владельца ещё предстоит проверить на VPS.

До успешной проверки рабочий файл сессии не заменяется. После проверки используется
атомарная замена с fsync. На Linux новый файл имеет права 0600, новый каталог — 0700.
Сессия по умолчанию находится в `secrets/source-session.json`, вне SQLite и её backup.
`source status` показывает только локальный статус, поколение и время последней
проверки; `installed` не означает новую онлайн-проверку при каждом чтении статуса.

## Worker и восстановление

После проверки доступа установите `EHTG_SOURCE_ENABLED=true` в `.env`. Запустите
API по README и worker отдельно:

```sh
uv run --locked --extra source ehtg worker
```

`ehtg worker --once` обрабатывает не более одного доступного анализа. При старте
worker проверяет поставку extractor. Без сессии запросы к источнику не выполняются:
работа получает `SOURCE_AUTH_REQUIRED`, анализы приостанавливаются.

Черновик и его работа анализа сохраняются одной транзакцией. Захват работы атомарен;
каждая попытка получает поколение и аренду. Heartbeat продлевает аренду, а завершение,
ошибка и продление проверяют актуальное поколение, владельца, ревизию и срок.
Старый процесс не может перезаписать новую попытку. Аварии также расходуют бюджет
попыток, поэтому повторяющиеся падения не создают бесконечный цикл.

Живой worker дополнительно держит межпроцессную блокировку источника. Истёкшей
аренды недостаточно для конкурентного обращения другого worker. Импорт и
возобновление используют ту же блокировку; при занятости возвращают `SOURCE_BUSY`.

Временная сеть получает до трёх попыток с задержками 5 и 10 секунд по умолчанию.
Время повтора записывается в SQLite; транзакция не удерживается во время ожидания
или сетевого вызова. Авторизация, квота или блокировка ставят общую паузу.
После устранения причины выполните:

```sh
uv run --locked --extra source ehtg source resume
```

Команда повторно проверяет установленную сессию и затем снимает паузу. Импорт
новой сессии сам по себе не возобновляет очередь. Автоматических уведомлений
пока нет: Telegram-бот будет добавлен следующим отдельным этапом.

В API черновик содержит `analysis.state`, `attempts`, `retry_at` в UTC, безопасные
`error_code`/`error_message` и `retryable`. Для владельца доступны операции:

- `POST /api/v1/drafts/{id}/analysis/cancel` — отменить незавершённый анализ.
- `POST /api/v1/drafts/{id}/analysis/retry` — новый анализ после ошибки/отмены.

Обе требуют свежий `If-Match`, меняют ревизию и делают старые результаты
недействительными. Эти операции не управляют принятой очередью публикаций.

## Сетевая и процессная изоляция

Из gallery-dl вызывается только парсер метаданных, без инициализации его сетевой
сессии, CLI, дочерних extractors, postprocessors, избранного, оригиналов и сброса квоты.
Страницы загружает собственный транспорт:

- Только HTTPS и точный `e-hentai.org`, допустимые `home.php` и gallery-пути.
- Все DNS-ответы проверяются; внутренние, служебные и multicast адреса отклоняются.
- Подключение идёт к уже проверенному IP с TLS/SNI исходного hostname и сверкой peer IP.
- HTTP-перенаправления не выполняются; cookies не попадают к другим host или медиа.
- Переменные proxy, API/bot tokens и пользовательские настройки Python/gallery-dl
  дочернему процессу не наследуются.
- Сырые stdout/stderr и тексты исключений источника не попадают в историю/API.

Частота всех обращений, включая проверку сессии, ограничивается общей записью
SQLite; по умолчанию интервал 3 секунды. Разметка страниц индекса обходится по
реальным ссылкам пагинации, без предположения о числе миниатюр. Все позиции должны
быть представлены; пропуски или конфликт идентичности не считаются успехом.

По умолчанию HTML ограничен 2 MiB, обход — 200 страницами индекса, попытка —
900 секундами, stdout — 2 MiB. В Linux у процесса ограничены адресное пространство
(256 MiB), CPU (120 секунд), отключены core dumps. Смерть родителя завершает процесс
через PDEATHSIG; отмена/потеря аренды завершает процесс и не принимает его результат.
Загрузка медиа и запуск сторонних команд в этом процессе не реализованы.

Windows служит окружением разработки: Unix-лимиты и PDEATHSIG там не применяются.
На целевом Linux реальные ресурсные пределы ещё требуют проверки. Работа с proxy
и медиа-узлами в эту версию не входит; настройки маршрутизации VPS не изменялись.

## Что ещё не проверено

С реальным аккаунтом и IP VPS пока не проверялись вход, HTML источника, блокировки,
нагрузка и совместимость с 3x-ui. Изображения не скачиваются, обложка пока является
метаданными без сетевого предпросмотра. Подпись не формируется, публикации не
исполняются. Эти проверки и стадии остаются в плане разработки.
