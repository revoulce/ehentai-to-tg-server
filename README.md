# Сервер E-Hentai → Telegram

Первый этап разработки: общее ядро для HTTP API, будущего Telegram-бота и worker.
Они используют одни правила подтверждения и одну SQLite-БД. Начать с этой части
важнее, чем с интерфейса: сохранность очереди, ревизии и защита от дублей определяют
контракт обоих клиентов и безопасное восстановление.

Стек: Python **3.12.14**, FastAPI, Pydantic 2, SQLite из Python runtime, uv.
Точные версии прямых и транзитивных зависимостей с хешами находятся в `uv.lock`;
инструмент сборки также закреплён. Локальная проверка выполнена с SQLite **3.53.1**.
SQLite runtime в будущей Linux-сборке проверяется отдельно; Docker-образ ещё не создан.

## Что работает

- Канонизация ссылок `/g/{gid}/{token}/` в HTTPS, строгая проверка источника.
- Диапазоны/исключения страниц, сортировка, устранение повторов и проверка границ.
- Черновики, неизменяемые снимки метаданных/идентичности страниц и ревизии.
- Атомарная запись задания, страниц, ключа идемпотентности и события в SQLite.
- Защита от конкурентного подтверждения и постановки той же галереи в очередь.
- Восстановление ответа подтверждения тем же ключом после рестарта.
- Постоянная очередь FIFO и курсорный список заданий.
- Коды сопряжения с 128 битами энтропии, сроком 5 минут и атомарным погашением;
  токены устройств с 256 битами энтропии, хранение хешей и отдельный отзыв.
- Привязка токена к разрешённому origin расширения; CORS и проверка Host.
- Ограничение размера тела, в том числе потокового, и безопасные ошибки с request ID.
- Последовательные SQL-миграции с проверкой хешей и согласованный SQLite backup.

Это ещё не работающий репостер. **Нет** обращения к E-Hentai, адаптера gallery-dl,
импорта cookies, анализа галерей, скачивания, обработки изображений, исполняющего
worker и Telegram-бота/публикации. Пакет gallery-dl намеренно не добавлен до
технического прототипа и проверки конкретной поставки. `/s/` пока отклоняется.
Batch, подписи, явный повтор, отмена/повторы заданий и ручная сверка — следующие этапы.

`POST /drafts` сохраняет черновик в `analyzing`; без будущего анализатора он останется
в этом состоянии. HTTP-клиент не может загрузить собственный снимок или обойти
подтверждение готового предпросмотра. В тестах анализ имитирует только синтетическая
фикстура через внутренний `record_analysis`. Принятые задания сохраняются в `queued`
и пока не исполняются. `/capabilities` и `/status` отражают эти ограничения.

## Локальный запуск

Установите Python 3.12.14 и uv 0.13.x; зафиксированная проверенная версия uv — 0.13.1.
Работайте из каталога `backend`.

```sh
uv sync --locked
```

Скопируйте `.env.example` в `.env`, замените ID владельца/канала и точный origin
расширения. Массивы настроек задаются JSON. Без разрешённого origin сопряжение
закрыто. Пример ID расширения — заполнитель, устанавливаемого клиента пока нет.
Не храните реальные `.env`, данные и секреты в Git.

```sh
uv run --locked ehtg migrate
uv run --locked uvicorn ehtg.api.app:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

Миграции также применяются при старте приложения до приёма запросов. Сервер по
умолчанию доступен только локально. `/healthz` — публичная минимальная проверка БД;
прикладные маршруты находятся под `/api/v1` и требуют токен устройства.
Для внешнего доступа требуется проверенный HTTPS-прокси, allowlist Host/origin и
обследование VPS по исходному ТЗ. Не публикуйте этот прототип в интернете.

Для разработки вместо будущей команды бота `/pair` доступна доверенная команда
на сервере:

```sh
uv run --locked ehtg pair
```

Она показывает одноразовый код только в терминале администратора. Код передаётся
в JSON на `POST /api/v1/pairing/redeem` с `device_name` и заголовком `Origin` из
allowlist. Токен возвращается только один раз; потеря ответа требует нового кода.
Прикладные запросы используют `Authorization: Bearer …` и тот же `Origin`.
Ограничение обменов общее для установки, хранится в SQLite и переживает рестарт:
по умолчанию 10 попыток за минутное окно, включая неудачные попытки.

HTTP-предпросмотры возвращают `ETag`, например `"2"`. `PATCH /drafts/{id}` и
`POST /drafts/{id}/publish` требуют соответствующий `If-Match`. Для подтверждения
нужны тело `{}` и `Idempotency-Key` из 1–128 символов `A-Za-z0-9._:-`. Ревизия входит
в хеш подтверждения; повтор ключа с другой ревизией даёт `409`.

Публичная Swagger-страница отключена. Типизированный контракт можно экспортировать
без запуска сервера:

```sh
uv run --locked ehtg export-openapi docs/openapi.json
```

## Проверки и сборка

```sh
uv run --locked ruff check src tests
uv run --locked ruff format --check src tests
uv run --locked mypy src
uv run --locked pytest
uv build --no-sources
```

CI выполняет эти проверки на Ubuntu и Windows. Фактический запуск CI в GitHub
потребует публикации репозитория; сейчас проверки выполнены локально на Windows.
Результаты: **61 тест проходит**, Ruff/mypy без ошибок, wheel/sdist собираются;
подробности — в [отчёте проверок](docs/verification.md).
Тесты используют временную БД и синтетические данные; сеть, реальные галереи и
Telegram не вызываются. ASGI TestClient использует внутренние loopback-сокеты;
в окружениях с запретом сокетов ему нужно разрешение на локальную работу.

## Хранение и backup

По умолчанию БД — `data/db/app.sqlite3` на локальном диске. Соединения включают
foreign keys, busy timeout 5 секунд и `synchronous=FULL`; база использует WAL.
Запись выполняется короткими `BEGIN IMMEDIATE` транзакциями. Синхронные операции
SQLite в HTTP выполняются в thread pool, вне event loop.

```sh
uv run --locked ehtg backup backups/app-2026-10-18.sqlite3
```

Путь backup должен быть новым; существующие файлы не перезаписываются. Используется
SQLite backup API. Для восстановления остановите приложение и установите копию
как `EHTG_DATABASE_PATH`, затем выполните `ehtg migrate`. Простое копирование
открытого основного файла без WAL не заменяет согласованный backup.
Хеши токенов в backup всё равно требуют ограничения доступа. Источник/секреты сессии
будут храниться отдельно, когда появится адаптер.

## Устройство проекта

```text
src/ehtg/
  domain/       # чистые правила URL, страниц, снимков и ошибок
  storage/      # соединения, миграции и backup
  service.py    # общие сценарии черновиков и подтверждения
  auth.py       # сопряжение и отзываемые устройства
  api/          # FastAPI, входные/выходные схемы и HTTP-границы
  cli.py        # доверенные серверные команды
```

Бот и worker добавятся как отдельные адаптеры этого пакета, а не отдельные
реализации правил. Части репозитория не выполняют сетевые вызовы в транзакциях БД.
Лицензия на сторонний код не предполагается: исходники рассмотренных репостеров
не копировались; поставка и notices для будущего gallery-dl ещё требуют проверки.

Основания решений: [структура приложений FastAPI](https://fastapi.tiangolo.com/tutorial/bigger-applications/),
[SQLite в Python](https://docs.python.org/3.12/library/sqlite3.html),
[WAL и сохранность](https://www.sqlite.org/wal.html),
[locking/sync uv](https://docs.astral.sh/uv/concepts/projects/sync/).
Исходное ТЗ — `../docs/technical-specification.md`; порядок дальнейших работ —
в [плане разработки](docs/development-plan.md).
